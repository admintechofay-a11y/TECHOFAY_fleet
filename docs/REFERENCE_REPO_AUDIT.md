## 1. Executive Context & Stack Discrepancy

The reference repository (`Transport_techofay`) implements a logistics and fleet system built on:
- **Backend:** Laravel 10 (PHP 8.2), MySQL, Redis, Fleetbase core packages.
- **Frontend:** React 19, TypeScript, Vite, TailwindCSS, Zustand.
- **Audit Findings:** Previously documented in `Transport_techofay/AUDIT_REPORT.md` with 11 distinct defect categories (including multi-tenant isolation fallbacks, hardcoded demo login bypasses, split data authority between MySQL and LocalStorage, missing route registrations, and React infinite render cascades).

**Architectural Decision:** Under SOW Principle 2, the new platform **must be built on the MERN stack (MongoDB, Express.js, React, Node.js, TypeScript)**. We will **not** copy the Laravel framework, Fleetbase submodules, or PHP dependencies. Instead, we extract proven domain workflows, business logic formulas, state machine transitions, and UI paradigms while avoiding known reference defects.

## 3. Reference Items Strictly Prohibited from Reuse
1. **No Laravel / PHP Backend Code:** The backend must be 100% Node.js / Express / TypeScript.
2. **No Fleetbase Submodules or Vendor Bloat:** Do not clone or submodule third-party Fleetbase modules.
3. **No Hardcoded Demo Credentials or Auto-SuperAdmin Generation:** All authentication must follow secure zero-trust principles.
4. **No Client-Side LocalStorage Persistence for Business Records:** All operational data belongs in MongoDB.
5. **No Fake Success Mocks in Production Paths:** If WhatsApp credentials or S3 buckets are missing, the UI must clearly state `Not Configured`.
